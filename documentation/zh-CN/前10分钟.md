# 60 秒看到一条追踪

[English](../first-10-minutes.md) | [Español](../es/primeros-10-minutos.md) | [Português](../pt-BR/primeiros-10-minutos.md) | **简体中文**

没有日志语句,没有测试框架,事后也不用打开任何文件。一个普通脚本,运行一次,追踪就打印在你的
终端里。下面的一切都真实运行在已发布的 `@narrativetrace/core-node` 和 `@narrativetrace/proxy`
包上(0.1.1,撰写本文时 npm 上的在线版本——运行 `npm view @narrativetrace/core version` 可以
看到你阅读本文时的当前版本)——输出是粘贴过来的,不是想象出来的。需要 Node 20+(已发布的
`@narrativetrace/core` 包在 `engines` 字段里声明了这一点);下面示范用 pnpm,npm 也能用,第 1
步里会说明一处差异。

## 1. 新建项目,添加依赖包

```bash
mkdir narrativetrace-quickstart && cd narrativetrace-quickstart
pnpm init
pnpm add @narrativetrace/core-node @narrativetrace/proxy
```

`core-node` 重新导出了 `@narrativetrace/core` 中的所有内容,并注册了 Node id 生成器——单独
导入 `@narrativetrace/core` 会在第一次被追踪的调用时抛出异常。`pnpm init` 写出的
`package.json` 带有 `"type": "module"`,所以下面的 `import` 语法不需要任何额外配置就能用。用
npm?`npm init -y` 默认是 CommonJS——紧接着运行 `npm pkg set type=module`(在 `npm add`
之前),否则第 2 步里的 `import` 会报错:`SyntaxError: Cannot use import statement outside a
module`。

## 2. 程序代码

```js
// index.js
import { NarrativeTraceConfig, SyncNarrativeContext, renderMarkdownBody } from "@narrativetrace/core-node";
import { traceObject } from "@narrativetrace/proxy";

class OrderService {
  placeOrder(customerId, productId, quantity) {
    return `ORD-${customerId}-${productId}-${quantity}`;
  }
}

const context = new SyncNarrativeContext(new NarrativeTraceConfig());
const service = traceObject(new OrderService(), context, {
  placeOrder: ["customerId", "productId", "quantity"],
});

service.placeOrder("C1", "P1", 2);
console.log(renderMarkdownBody(context.captureTrace()));
```

`OrderService` 是一个普通的类——不需要接口,不需要基类,也不需要装饰器。`traceObject()` 用
ES `Proxy` 包装具体的实例;它的第三个参数提供了 `placeOrder` 的参数名,因为 JavaScript 在
运行时不会保留参数名。调用被包装后的对象而不是原始对象,它发起的每一次调用都会被记录进
`context`。

## 3. 运行它

```bash
node index.js
```

真实输出,来自产出这页内容的那次运行:

```text
- `OrderService.placeOrder(customerId: "C1", productId: "P1", quantity: 2)` → `"ORD-C1-P1-2"` — 0.5849169999999901ms
```

末尾的 `Nms` 是墙钟时间——在你的机器上会是不同的数字,下一次运行也会是另一个不同的数字。这
一行里其余的一切都是确定的:类名、方法名、参数名和参数值,以及返回值。

你没有写任何日志语句。这段叙事来自你的方法名、你的参数名,以及方法返回的值——这些信息本来
就已经在那里了。

## 刚刚发生了什么

- **一个上下文**(`new SyncNarrativeContext(new NarrativeTraceConfig())`)是记录调用的地方——
  一个普通对象,不是全局变量,也不是单例。(跨越 `await` 贯穿一次请求的 Node 代码需要改用
  `AsyncNarrativeContext`;参见[框架集成指南](框架集成指南.md)。)
- **包装**(`traceObject(new OrderService(), context, {...})`)是唯一一行为该对象打开追踪的
  代码。`OrderService` 本身没有任何改变——没有导入,没有基类,没有注解。如果类是你自己写的,
  也可以用 `@traced`/`@narrated` 装饰器代替参数名映射;参见[装饰器指南](装饰器指南.md)。
- **先捕获,再渲染**——`context.captureTrace()` 把发生的事情拍成一张快照,存进一棵普通的树;
  `renderMarkdownBody()` 只是众多可以作用于这棵树的渲染器之一。`renderIndentedText()` 会画出
  一棵 ASCII 树,`@narrativetrace/diagrams` 能把它转成 Mermaid 或 PlantUML 时序图,
  `@narrativetrace/browser` 的 `renderToConsole()` 则会把它排版后打印到浏览器 DevTools 的
  控制台里。

## 把它发送到你的日志库

上面的控制台那一行只是作用于这条追踪的众多渲染器之一;同一条追踪也可以直接流入你在生产环境
中已经在用的日志库。加上 [Pino](https://github.com/pinojs/pino) 桥接(如果 Winston 才是你的
日志库,`@narrativetrace/winston` 用法一样——把 import 换成 `createWinstonEventConsumer`):

```diff
-import { NarrativeTraceConfig, SyncNarrativeContext, renderMarkdownBody } from "@narrativetrace/core-node";
+import { NarrativeTraceConfig, SyncNarrativeContext, DualPathPipeline, BufferedEventConsumer, renderMarkdownBody } from "@narrativetrace/core-node";
 import { traceObject } from "@narrativetrace/proxy";
+import { createPinoEventConsumer } from "@narrativetrace/pino";
+import pino from "pino";

 class OrderService {
   placeOrder(customerId, productId, quantity) {
     return `ORD-${customerId}-${productId}-${quantity}`;
   }
 }

-const context = new SyncNarrativeContext(new NarrativeTraceConfig());
+const logger = pino();
+const pinoConsumer = createPinoEventConsumer(logger, { levels: { enter: "info", return: "info" } });
+const pipeline = new DualPathPipeline(pinoConsumer, new BufferedEventConsumer());
+const context = new SyncNarrativeContext(new NarrativeTraceConfig(), undefined, pipeline);
 const service = traceObject(new OrderService(), context, {
   placeOrder: ["customerId", "productId", "quantity"],
 });

 service.placeOrder("C1", "P1", 2);
 console.log(renderMarkdownBody(context.captureTrace()));
```

```bash
npm add @narrativetrace/pino @narrativetrace/observability pino
node index.js
```

真实输出,来自产出这页内容的那次运行:


和上面的耗时一样,每一个与本次运行相关的字段(`time`、`pid`、`hostname`、`trace_id`、
`span_id`、`nt.traceName`)在你的机器上、以及每次运行时都会是不同的值;两行 JSON 和中间那行
markdown 的结构本身不会变。这证明了追踪确实到达了你已经拥有的落地点,而控制台输出完全没有被
改动。完整配置(按事件设置级别、用于给你自己的日志行盖章的 `LogContext` mixin、Winston
配置):[框架集成指南 § Winston 与 Pino](框架集成指南.md#9-winston-与-pino)。
