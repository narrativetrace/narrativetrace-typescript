# NarrativeTrace TypeScript 装饰器指南

[English](../decorators-guide.md) | [Español](../es/guia-de-decoradores.md) | [Português](../pt-BR/guia-de-decoradores.md) | **简体中文**

本指南介绍方法级追踪元数据——参数名、叙述文本、错误上下文和脱敏。**默认的声明方式是 `traceObject()` 上的配置形式**,写在组合根处;四个装饰器则是同样的声明换了一种更顺手的语法,面向已经在编译装饰器的项目(NestJS、Angular,以及任何 TypeScript 5+ 应用)。

NarrativeTrace 遵循**代码即日志**的理念:方法名、参数名和返回值本身就应当讲清运行时的故事。请首先保持业务逻辑干净、富有表达力,元数据只在例外情况下添加,而不是默认添加——只有当它能带来具体的额外价值时才添加,例如有针对性的叙述文本、面向特定错误的上下文,或敏感数据脱敏。

## 配置形式——在包装处声明一切

`traceObject()` 接受按方法的配置,能表达装饰器所能表达的一切。它不需要编译装饰器,适用于普通对象和纯 JavaScript,并让追踪元数据与接线代码放在一起:

```ts
import { traceObject } from "@narrativetrace/proxy";

const payments = traceObject(paymentService, context, {
  methods: {
    charge: {
      params: ["customerId", "amount", "cardToken"],       // @traced 的孪生
      narration: "Charging {amount} to {customerId}",      // @narrated 的孪生
      onError: [                                           // (叠加的)@onError 的孪生
        { template: "Charge failed for {customerId}" },
        { exception: CardDeclinedError, template: "Card declined for {customerId}" },
      ],
      notTraced: [2],                                      // @notTraced 的孪生——脱敏 cardToken
    },
  },
});
```

每个配置轴与一个装饰器一一对应:

| 配置轴 | 孪生装饰器 | 含义 |
|---|---|---|
| `params: ["a", "b"]` | `@traced("a", "b")` | 按位置的参数名 |
| `narration: "…{a}…"` | `@narrated("…{a}…")` | 进入时的叙述模板 |
| `onError: "…"` 或 `[{ exception?, template }]` | `@onError("…")` / 叠加的 `@onError(Type, "…")` | 抛出时的错误上下文;最具体的类型胜出 |
| `notTraced: [1, 2]` | `@notTraced(1, 2)` | 按索引脱敏参数 |

简写:纯字符串的 `onError` 是兜底(`@onError("...")` 的孪生);当你只需要参数名时,第三个参数依然接受简单的名称映射 `traceObject(service, context, { placeOrder: ["customerId"] })`。

**优先级:** 已配置的轴会整体覆盖该方法对应装饰器的元数据;未配置的轴保留装饰器的声明。因此配置与装饰器可以组合——库中的类可以带着装饰器,而组合根依然可以覆盖其中某一个轴。

## 装饰器一览

| 装饰器 | 模块 | 作用目标 | 用途 |
|---|---|---|---|
| `@traced()` | `@narrativetrace/proxy` | 方法 | 为追踪输出绑定参数名。 |
| `@narrated()` | `@narrativetrace/proxy` | 方法 | 为被追踪的方法添加人类可读的叙述文本。 |
| `@onError()` | `@narrativetrace/proxy` | 方法 | 在方法抛出异常时添加上下文相关的错误文本。 |
| `@notTraced()` | `@narrativetrace/proxy` | 方法 | 将参数值标记为在追踪输出中脱敏。 |

四个装饰器在**两种装饰器方言**下都能工作:TypeScript 5+ 默认编译的标准 [TC39 装饰器](https://github.com/tc39/proposal-decorators),以及 NestJS 和 Angular 项目编译的旧式 `experimentalDecorators` 方言。方言在运行时按调用形态自动识别——无需任何配置,同一个导入两种方言通用,发布的类型声明在两种编译器设置下都能通过类型检查。如果你的环境根本不编译装饰器(纯 JavaScript,或把 `@` 语法原样保留的构建),装饰器调用会抛出指明修复方法的错误,而不是默默地什么都不记录——修复方法就是 `traceObject()` 上等价的配置形式(在下文每个装饰器处给出)。

## `@traced`

使用 `@traced` 绑定显式的参数名。当压缩工具(minifier)会剥离参数名,或者你希望在追踪中使用更具描述性的名称时,这一点至关重要。

```ts
import { traced } from "@narrativetrace/proxy";

class OrderService {
  @traced("customerId", "productId", "quantity")
  placeOrder(cId: string, pId: string, qty: number) {
    // ...
  }
}
```

工作原理:

- 参数名存储在一个以方法函数为键的 `WeakMap` 中。
- 当 `traceObject()` 拦截一次调用时,会查找这些名称,并用它们代替 `arg0`、`arg1` 等。
- 名称是按位置对应的——它们通过索引与参数建立映射。

### 不使用 `@traced`(手动指定参数名)

如果你无法使用装饰器,或者不想使用,可以直接将参数名传给 `traceObject()`:

```ts
const traced = traceObject(orderService, context, {
  placeOrder: ["customerId", "productId", "quantity"],
  cancelOrder: ["orderId"],
});
```

这等价于 `@traced`,但无需任何装饰器支持即可运行。同样的名称也可以放进完整配置形式的 `methods.placeOrder.params`(见上文配置一节);两者都给出时,`methods.<名称>.params` 胜过简单映射。

## `@narrated`

`@narrated` 是一个逃生舱(escape hatch),不是添加叙述的标准方式——默认路径
完全由方法自身的名字、参数和结果派生而来。需要用到模板,本身就是一个信号,
和清晰度评分要标记的信号是同一种:说明代码没能自己把它做的事说清楚。在写
模板之前,先想一想方法名是不是真正的问题——一个更好的名字能修好经过这个
方法的每一条追踪,而不只是这一行。

当你确实希望追踪中出现一句明确的句子,而不是只依赖方法名加参数时,再刻意使用 `@narrated`。

```ts
import { narrated } from "@narrativetrace/proxy";

class OrderService {
  @narrated("Placing order of {quantity} units for customer {customerId}")
  placeOrder(customerId: string, quantity: number) {
    // ...
  }
}
```

工作原理:

- 叙述模板存储在一个以方法函数为键的 `WeakMap` 中。
- 该模板字符串会附加到追踪节点的 `MethodSignature.narration` 字段上。
- 与 `traceObject()` 配合使用——叙述文本会以斜体形式出现在 Markdown 输出中调用记录的下方。

占位符的解析方式:`{paramName}` 会替换为对应名称的参数;`{param.property}` 会在原始参数对象上调用相应的 getter。只会解析单个属性层级——`{order.card.number}` 永远不会被解析,占位符会原样保留。通过属性路径抵达的被脱敏成员,解析结果为 `[REDACTED]`,而不是原始值——参见下文 `@notTraced` 部分的脱敏说明。

配置孪生——不用装饰器实现同样的叙述:

```ts
const traced = traceObject(orderService, context, {
  methods: {
    placeOrder: {
      params: ["customerId", "quantity"],
      narration: "Placing order of {quantity} units for customer {customerId}",
    },
  },
});
```

## `@onError`

使用 `@onError` 为异常附加特定于上下文的消息。

```ts
import { onError } from "@narrativetrace/proxy";

class PaymentService {
  @onError("Payment declined for customer {customerId}, amount was {amount}")
  charge(customerId: string, amount: number) {
    // ...
  }
}
```

工作原理:

- 错误上下文模板存储在一个以方法函数为键的 `WeakMap` 中。
- 当方法抛出异常时,错误上下文会附加到追踪节点的 `MethodSignature.errorContext` 字段上。
- 在异常消息之外,为错误追踪补充特定于业务领域的上下文信息。
- 可以叠加多个——把 `@onError(NotFoundError, "…")` 叠在 `@onError("…")` 之上——抛出时,与所抛类型匹配最具体的声明胜出。

配置孪生——字符串是兜底,数组形式承载带类型的声明:

```ts
const traced = traceObject(paymentService, context, {
  methods: {
    charge: {
      params: ["customerId", "amount"],
      onError: [
        { template: "Payment declined for customer {customerId}, amount was {amount}" },
        { exception: InsufficientFundsError, template: "Insufficient funds for {customerId}" },
      ],
    },
  },
});
```

## `@notTraced`

使用 `@notTraced` 对敏感的参数值进行脱敏。

```ts
import { notTraced } from "@narrativetrace/proxy";

class AuthService {
  @notTraced(1) // 对索引为 1 的参数进行脱敏
  login(username: string, password: string) {
    // ...
  }
}
```

工作原理:

- 参数索引存储在一个 `WeakMap<Function, Set<number>>` 中。
- Proxy 会在追踪输出中将被脱敏的参数渲染为 `[REDACTED]`。
- 对于被脱敏的参数,`ParameterCapture.redacted` 会被设为 `true`。
- 可以同时脱敏多个索引:`@notTraced(1, 2)`。
- **`@notTraced` 并不是参数被脱敏的唯一途径。** 在 `traceObject()` 下,每个被捕获参数自己的*名字*也会拿去和
  `RedactionPolicy` 基于名称的拒绝列表比对,和对象字段名的处理方式完全一样——`pay(policyId, paymentToken)`
  会脱敏 `paymentToken`,不需要任何装饰器,因为 `token` 就在拒绝列表里。当参数名完全看不出线索时
  (例如 `pay(id, value)`,这里 `value` 是一个机密),`@notTraced` 仍然重要。这条基于名字的一半轴
  是 `traceObject()`(proxy)特有的;NestJS 的 `AutoProxyModule` 自动包装完全没有办法还原参数的真实
  名字(每个参数都渲染成 `arg0`、`arg1`……),所以在那里只有 `@notTraced` 和基于值形状的脱敏能保护
  参数——完整说明见[隐私与脱敏](隐私与脱敏.md)。
- 对于**对象字段**,声明一个静态类字段:`static notTraced = ["pan", "secret"]`
  ——这些属性会在内省期间渲染为 `[REDACTED]`,与基于名称的 `RedactionPolicy` 拒绝列表
  (该列表已覆盖 `password`、`token`、`ssn`、`cvv` 等——且默认即为多语言:`contraseña`、`senha`、`motDePasse`、`密码` 等)相互独立。
- 典型用例:密码、token、机密、卡片数据。
- 配置孪生:在 `traceObject()` 上写 `methods.login.notTraced = [1]`——同样的索引,无需装饰器。

**脱敏优先于点名它的模板。**`@narrated` 与 `@onError` 会在原始参数上解析
`{param.property}` 路径,而抵达被脱敏成员的路径解析结果为 `[REDACTED]`——无论该成员是被
基于名称的拒绝列表覆盖,还是被显式列在 `static notTraced` 中。一个直接点名某个值的裸占位符
`{name}` 同样遵循这两条规则:拒绝列表会像检查字段名一样检查这个键名,值本身的形态也会被检查,
因此 `@narrated("login {password}")` 和以 `{value}` 形式出现的 JWT 都会渲染为 `[REDACTED]`。
无论点名一条路径,还是点名某个值,都绝不会削弱直接作用于该值的规则:

```ts
class Card {
  static readonly notTraced = ["cvv"];
  constructor(readonly last4: string, readonly cvv: string) {}
}

class PaymentService {
  @narrated("Charging card ending {card.last4}, cvv {card.cvv}")
  @traced("card")
  charge(card: Card) { /* ... */ }
}
// narration: "Charging card ending 4111, cvv [REDACTED]"
```

如果你确实需要在叙述中呈现该值,请将其从 `static notTraced` 中移除(或从其匹配的拒绝列表
模式中移除)——这一移除动作才是刻意做出、可供评审的决定。占位符点名了对象上不存在的属性,
这是书写上的笔误,而不是脱敏决定:它会原样保留,并且测试期间的未解析占位符警告仍然会为它
触发。

## 目标绑定的取舍——自调用不会嵌套

被追踪的方法执行时,`this` 绑定的是原始对象而不是代理(方法包装器内部的 `Reflect.apply(fn, target, args)`)。因此,方法调用同一对象上的兄弟方法(`this.validate(order)`)时,调用的是原始方法——调用会正确执行,但不会被捕获,所以自调用永远不会以嵌套 span 的形式出现。这是刻意的设计取舍,不是缺陷:绑定原始对象让代理免疫 Proxy 的几大经典陷阱——`#private` 字段(经代理接收者访问会抛出)、带内部槽的内置对象(`Map`、`Date`)和箭头函数字段。

嵌套来自包装协作者,这也是唯一的结构规则:**拆分为协作者服务,在每个服务被构造的地方将其包装。**

```ts
// 一个类,自调用:只有 placeOrder 被捕获。
class OrderService {
  placeOrder(customerId: string) {
    this.reserveStock(customerId);   // 会执行,但不被捕获
    this.charge(customerId);         // 会执行,但不被捕获
  }
  // ...
}

// 在组合根处包装协作者:得到完整的嵌套叙事。
const inventory = traceObject(new InventoryService(), context);
const payments = traceObject(new PaymentService(), context);
const orders = traceObject(new OrderService(inventory, payments), context);
```

## 纯净性契约——追踪期间的副作用

NarrativeTrace 在渲染追踪时,可能会调用你的对象上一小组固定的代码路径。请保持这些成员
**纯净**——不含懒加载、访问计数器、缓存填充或 I/O 等副作用——就像面对调试器或序列化器时
那样。

哪些会被调用,哪些不会:

- **内省会枚举自身可枚举属性**(`Object.keys`)。定义在类上的 getter 存在于原型上,
  永远不会被枚举,因此也永远不会在内省期间运行。(直接定义在对象字面量上的访问器*确实*是
  自身可枚举的,会被运行——请优先使用类 getter,或者在 `static notTraced` 中标记该字段。)
- **自定义的 `toString()`(自身定义,非默认实现)只有在叶子节点上才会被调用**——也就是
  一个*完全没有自有字段*的对象。你的类型一旦有了哪怕一个自有字段,渲染期间就永远不会调用
  `toString()`;取而代之的是字段内省,不管你的 `toString()` 本来会打印出什么(家族级
  不变量,2026-09-11——原因见[隐私与脱敏](隐私与脱敏.md):在一个有字段的类型上信任精心
  编写的 `toString()`,正是一个*嵌套*对象自己的秘密曾经借以泄露的那条路径,而且是在任何
  逐字段检查都够不到的更深一层)。
- **`@narrativeSummary` 无论字段情况都会被调用**,并且依然会压过对 `toString()` 的信任
  和字段内省——它是你专门*为这条 trace* 写的代码,所以总是会运行,它的输出也总是被优先
  采用,不管这个类型是不是叶子节点。它的输出同样会被扫描是否具有秘密形状(JWT、卡号等)
  作为额外的防御层。
- 你在 `@narrated`/`@onError` 模板中点名的任何属性路径也会被调用——`{order.total}`
  通过属性访问来解析,因此被点名的 getter *会*运行。
- **调用是有界且隔离的。** 输出有上限(`maxStringLength`、`maxArrayItems`、
  `maxObjectKeys`);抛出异常的 getter 只会让*那一个字段*降级为带类型的错误标记
  `<error: 构造函数名>`(绝不会显示 `.message`,因为里面可能携带着那个成员本来拒绝渲染
  的确切值)——同级字段照常正常渲染。抛出异常的 `toString()` 或 `@narrativeSummary()`
  会以同样的方式让整个值降级;这两者都永远不会导致被追踪的业务调用失败(模板会回退为
  字面量 `{placeholder}`)。值会在调用点被立即(eager)渲染,因此任何副作用只发生一次,
  发生在确定的时间点。Thenable 对象永远不会被等待(await)——它们会渲染为 `<pending>`。

如果某个成员无法保持纯净,就把它列入 `static notTraced`——被脱敏成员的值根本不会被读取
——或者为该类型提供精心编写的 `@narrativeSummary`,由你精确控制会访问到什么;自定义的
`toString()` 只对完全没有自有字段的类型有用,因为有字段的类型无论 `toString()` 返回
什么都会被内省。当上下文处于非激活状态时(级别为 `off`,或在 `summary` 级别下参数捕获
被禁用),完全不会进行任何参数渲染——快路径上不会触碰任何用户代码。

## 组合使用装饰器

装饰器可以在同一个方法上叠加使用:

```ts
import { traced, narrated, onError, notTraced } from "@narrativetrace/proxy";

class TransferService {
  @traced("fromAccountId", "toAccountId", "amount", "authToken")
  @narrated("Transferring {amount} from {fromAccountId} to {toAccountId}")
  @onError("Transfer rejected for source account {fromAccountId}")
  @notTraced(3) // 对 authToken 进行脱敏
  transfer(from: string, to: string, amount: number, token: string) {
    // ...
  }
}
```

这一个方法就组合了参数命名、叙述、有针对性的错误上下文,以及参数脱敏。

## 完整示例

```ts
import { NarrativeTraceConfig, SyncNarrativeContext, renderMarkdown } from "@narrativetrace/core";
import { traceObject, traced, narrated, onError, notTraced } from "@narrativetrace/proxy";

class PaymentService {
  @traced("customerId", "amount", "token")
  @narrated("Charging {amount} to customer {customerId}")
  @onError("Payment failed for customer {customerId}")
  @notTraced(2) // 对 token 进行脱敏
  charge(customerId: string, amount: number, token: string) {
    if (amount > 1000) throw new Error("Amount exceeds limit");
    return { transactionId: "TX-1", amount };
  }
}

const config = new NarrativeTraceConfig();
const context = new SyncNarrativeContext(config);
const traced = traceObject(new PaymentService(), context);

traced.charge("C1", 500, "tok_secret_123");
console.log(renderMarkdown(context.captureTrace()));
```
