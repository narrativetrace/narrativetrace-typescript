# 智能体技能

[English](../agent-skills.md) | [Español](../es/habilidades-de-agente.md) | [Português](../pt-BR/habilidades-de-agente.md) | **简体中文**

*(since 0.1.3, unreleased)*

NarrativeTrace 提供**技能(skill)**:一种可供智能体加载的流程,它会运行经过测试的命令,并以 `verify` 步骤作为完成的判定标准——而不是一份智能体可能读、也可能不读的文档。技能在设计上刻意保持轻量:检查、诊断或生成的逻辑都放在经过测试的库代码里;技能自身的工作只是判断何时该出手、调用那些经过测试的代码,并结合上下文解读结果。

## 两个技能:准备与诊断

- **`add-narrative-tracing`**——把 NarrativeTrace 装进一个项目,并让它产出第一条追踪:用真实的工具链安装、包装一个类、渲染并运行第一条追踪,然后接入一个真正的日志系统(相当于 SLF4J 的角色:pino/winston/OpenTelemetry)。最后运行一次 `npx narrativetrace doctor` 并把接力棒交出去——这是两个技能之间的接缝。
- **`narrativetrace-doctor`**——只负责诊断,而且是**只读的**:从不编辑、生成或删除任何文件。运行经过测试的 CLI,读取它的报告,并走完那些单靠一份 CLI 输出覆盖不到的部分:在测试里证明脱敏生效、在断言之前先阅读一份已生成的追踪、以及审批追踪流程(标记为尚未研究——它自己的评测单元仍待完成)。

这两个技能可以组合使用:一个全新的项目从 `add-narrative-tracing` 开始;一个已经装好 NarrativeTrace、但哪里不对劲的项目,从 `narrativetrace-doctor` 开始。不管走哪条路,最终都会落到 doctor 这里——从此往后的诊断由它负责。生成部分(比如今天 doctor 只能提醒你去添加的那个脱敏证明测试)会由未来的另一个技能负责。

## 安装方式

- **Claude Code**:本仓库中已有生成好的 `SKILL.md`,分别位于 [`.claude/skills/add-narrative-tracing/`](../../.claude/skills/add-narrative-tracing/SKILL.md) 和 [`.claude/skills/narrativetrace-doctor/`](../../.claude/skills/narrativetrace-doctor/SKILL.md),每个目录都以其技能的规范名称命名——Claude 插件的前缀是唯一可以合法使用缩短片段的地方,而本仓库里没有任何东西是插件。把其中任意一个目录复制到你自己项目的 `.claude/skills/<名称>/` 下,Claude 就会自动识别它,可以直接按名字(`add-narrative-tracing` / `narrativetrace-doctor`)调用。
- **任意智能体、任意平台**:任何会读取 `AGENTS.md` 的智能体都能看到本仓库 `AGENTS.md` 自身在 `<!-- narrativetrace:skills:start -->` 标记之间携带的常驻提示——这两个技能的名字和描述,这样一个从未想过要去找它们的智能体也能知道它们的存在。
- **Codex**:生成好的 `SKILL.md` 也同样存在于 [`.agents/skills/add-narrative-tracing/`](../../.agents/skills/add-narrative-tracing/SKILL.md) 和 [`.agents/skills/narrativetrace-doctor/`](../../.agents/skills/narrativetrace-doctor/SKILL.md)——这是 Codex CLI 自己会发现的布局,它从工作目录向上一路找到仓库根目录(此外还会查看 `~/.agents/skills` 里的用户级全局技能)。它的 frontmatter 是 Claude 那一份的严格子集(只有 `name` 和 `description`——没有 `when_to_use`,也没有 `allowed-tools`),所以两种布局下发布的是完全相同的页面正文。来源:developers.openai.com/codex/skills 和 developers.openai.com/codex/concepts/customization(获取于 2026-09-13)。
- **Gemini,以及一个自动安装器**(由 `npx narrativetrace init` 帮你写好这些路径)已经在路线图上,但目前还没有实现——今天,复制生成好的文件就是可行的办法。

## 它们是如何构建的

这两个技能都从不手工编辑。`packages/skills/src/catalogue/add-narrative-tracing.ts` 和 `packages/skills/src/catalogue/narrativetrace-doctor.ts` 是这两个技能的真相来源;`pnpm run skills-render` 会据此重新生成这两个技能各自的 `.claude/skills/` 和 `.agents/skills/` 页面,以及本仓库自身 `AGENTS.md` 中的对应小节,而 `pnpm run skills-check`(已接入 `pnpm run check`)会在任何一份生成页面偏离类型化源头时立刻让构建失败。生成页面展示的每一段代码,都是通过本仓库其他文档同样使用的 `<!-- snippet: -->` 标记约定,从真实、经过测试的源代码中嵌入的——绝不是手工敲出来的示例。一条 A 级 lint 规则会把私有规划笔记的引用挡在两份页面之外:说明性的句子可以留下,点名那份笔记的引用不行。
