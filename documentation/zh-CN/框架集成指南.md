# NarrativeTrace TypeScript 框架集成指南

[English](../framework-integration-guide.md) | [Español](../es/guia-de-integracion-de-frameworks.md) | [Português](../pt-BR/guia-de-integracao-de-frameworks.md) | **简体中文**

本指南介绍如何将 NarrativeTrace 集成到 Web 应用和浏览器中,从 Express/Hono 中间件到浏览器渲染,再到跨异步上下文传播。

## 包

| 包 | 用途 |
|---|---|
| `@narrativetrace/core` | `SyncNarrativeContext`、`AsyncNarrativeContext` —— 上下文与渲染器 |
| `@narrativetrace/proxy` | `traceObject()` —— 基于 ES Proxy 的方法拦截 |
| `@narrativetrace/browser` | `renderToConsole`、`postToCollector` —— 浏览器专用输出 |
| `@narrativetrace/nestjs` | `AutoProxyModule`、`NoAutoProxy`、`NarrativeStorage` —— NestJS 自动代理模块 |
| `@narrativetrace/react` | `NarrativeTraceProvider`、`useTraced`、`useTraceCapture` —— React hooks 与 Provider |
| `@narrativetrace/react-router` | `useNavigationCapture` —— 按导航捕获追踪 |
| `@narrativetrace/opentelemetry` | `createOtelEventConsumer`、`TraceSpanExporter` —— OTel span 桥接 |
| `@narrativetrace/winston` | `createWinstonEventConsumer`、`createWinstonFormat` —— Winston 日志桥接 |
| `@narrativetrace/pino` | `createPinoEventConsumer`、`createPinoMixin` —— Pino 日志桥接 |

## 1. Express 中间件

使用 `AsyncNarrativeContext`(封装了 `AsyncLocalStorage`)实现按请求追踪:

```ts
import express from "express";
import { AsyncNarrativeContext, NarrativeTraceConfig, renderIndentedText } from "@narrativetrace/core";
import { traceObject } from "@narrativetrace/proxy";

const config = new NarrativeTraceConfig();
const asyncContext = new AsyncNarrativeContext(config);

const app = express();

// 中间件:为每个请求创建一个隔离的追踪上下文
app.use((req, res, next) => {
  asyncContext.run(() => {
    res.on("finish", () => {
      const tree = asyncContext.captureTrace();
      if (!tree.isEmpty) {
        console.log(renderIndentedText(tree));
      }
      // 每一个清理步骤都是独立的尽力而为(best-effort)——即使导出抛出异常,也不能跳过
      // reset。否则,这个请求的 span 会在共享管道中滞留,存活整个进程的生命周期
      //(内置的 `narrativeTrace()` 中间件——见下文本节“工作原理”一节——会为你完成这一步)。
      asyncContext.reset();
    });
    next();
  });
});

// 路由处理程序:追踪服务调用
app.get("/api/orders/:id", (req, res) => {
  const orderService = traceObject(new DefaultOrderService(/* deps */), asyncContext);
  const result = orderService.placeOrder(req.params.id, "P1", 2);
  res.json(result);
});

app.listen(3000);
```

### 工作原理

1. `AsyncNarrativeContext.run()` 会在 `AsyncLocalStorage` 内部为每个请求创建一个新的 `SyncNarrativeContext`
2. 请求内的所有被追踪调用共享同一个隔离的上下文
3. 响应结束时,追踪会被捕获、渲染,然后上下文被重置
4. 并发请求拥有完全隔离的追踪

### 自定义追踪导出

用你自己的导出器替换 `res.on("finish")` 处理程序——捕获、导出和重置三者相互独立,因此即使导出失败,重置依然会执行:

```ts
app.use((req, res, next) => {
  asyncContext.run(() => {
    res.on("finish", () => {
      try {
        const tree = asyncContext.captureTrace();
        if (!tree.isEmpty) {
          // 将追踪导出为 JSON,发送到你的可观测性平台
          const json = exportJson(tree, {
            scenario: `${req.method} ${req.path}`,
          });
          sendToCollector(json);
        }
      } finally {
        asyncContext.reset();
      }
    });
    next();
  });
});
```

## 2. Hono 中间件

与 Express 相同的模式,使用 Hono 的中间件 API:

```ts
import { Hono } from "hono";
import { AsyncNarrativeContext, NarrativeTraceConfig, renderIndentedText } from "@narrativetrace/core";
import { traceObject } from "@narrativetrace/proxy";

const config = new NarrativeTraceConfig();
const asyncContext = new AsyncNarrativeContext(config);

const app = new Hono();

// 中间件:按请求划分的追踪上下文
app.use("*", async (c, next) => {
  await asyncContext.run(async () => {
    try {
      await next();
    } finally {
      const tree = asyncContext.captureTrace();
      if (!tree.isEmpty) {
        console.log(renderIndentedText(tree));
      }
      // 即使上方的捕获/导出抛出异常也要重置——若请求级上下文未被重置,
      // 它的 span 就会泄漏进共享管道,存活整个进程的生命周期。
      asyncContext.reset();
    }
  });
});

app.get("/api/orders/:id", (c) => {
  const orderService = traceObject(new DefaultOrderService(/* deps */), asyncContext);
  const result = orderService.placeOrder(c.req.param("id"), "P1", 2);
  return c.json(result);
});

export default app;
```

## 3. 浏览器

`@narrativetrace/browser` 包为浏览器环境提供了两种输出机制。在浏览器中,请从
`@narrativetrace/core-web` 导入核心 API:它重新导出了 `@narrativetrace/core`,并注册了
Web Crypto id 生成器。若直接导入 `@narrativetrace/core`,则不会注册任何生成器,第一次被追踪的
调用就会抛出异常。

### 控制台渲染

使用 `console.group()` 和 `console.log()` 渲染追踪树,在 DevTools 中呈现层级化输出:

```ts
import { NarrativeTraceConfig, SyncNarrativeContext } from "@narrativetrace/core-web";
import { traceObject } from "@narrativetrace/proxy";
import { renderToConsole } from "@narrativetrace/browser";

const context = new SyncNarrativeContext(new NarrativeTraceConfig());
const traced = traceObject(orderService, context);

traced.placeOrder("C1", "P1", 2);
renderToConsole(context.captureTrace());
```

### 网络导出

将追踪树以 JSON 形式(即 `exportJson` 文档)通过 POST 发送到收集端点。无论 HTTP 状态码是
什么,该 Promise 都会以 `Response` 结果 resolve,只有在网络失败时才会 reject,因此需要检查
`response.ok`:

```ts
import { postToCollector } from "@narrativetrace/browser";

const tree = context.captureTrace();
const response = await postToCollector(tree, { scenario: "place order" }, "https://your-collector.example.com/traces");
if (!response.ok) console.warn(`collector rejected the trace: HTTP ${response.status}`);
```

一个完整实现上述所有功能的页面——点击时追踪、渲染进页面、同步镜像到控制台、POST 到开发用
收集端点——参见 `examples/browser`(`pnpm run example:browser`)。

### 不使用打包工具:纯 `<script>` 页面

常规包之间通过裸模块说明符(`"@narrativetrace/core"`)互相导入,浏览器无法自行解析这种写法。
对于不使用打包工具的页面,请使用 `@narrativetrace/standalone`:它把 `core-web` + `proxy` +
`browser` 打包进单个文件,既可以作为经典脚本使用(`dist/narrativetrace.global.js` →
`window.NarrativeTrace`),也可以作为 ES 模块使用(`dist/narrativetrace.js`)。可运行示例:
`examples/script-tag`(`pnpm run example:script-tag`)。

### 浏览器限制

核心上下文、ES Proxy 和值渲染都是纯 JavaScript 实现,没有任何 Node 依赖。浏览器中的差异如下:

| Feature | Browser | Node |
|---------|---------|------|
| 上下文 | `SyncNarrativeContext` | `SyncNarrativeContext` 或 `AsyncNarrativeContext` |
| 异步传播 | 通过 `snapshot()` 手动传播 | 通过 `AsyncNarrativeContext` 使用 `AsyncLocalStorage` |
| 计时 | `performance.now()` | `performance.now()` |
| 文件输出 | 不可用 | `writeTraceOutput()` |
| 控制台输出 | `renderToConsole()` | `renderIndentedText()` / `console.log()` |
| Id 生成器 | `@narrativetrace/core-web`(Web Crypto) | `@narrativetrace/core-node`(`node:crypto`) |
| 网络输出 | `postToCollector()` | 自定义(fetch/axios) |

### 浏览器中的手动异步传播

在没有 `AsyncLocalStorage` 的情况下,手动传播上下文:

```ts
const snapshot = context.snapshot();
const worker = new SyncNarrativeContext(config);

// 包装异步回调
someAsyncApi.onComplete(() => {
  snapshot.wrapFn(worker, () => {
    // 这里的被追踪调用会加入快照上下文的追踪,并从它们被发布的那一刻起
    // 就会被该上下文的 captureTrace() 报告——而不是只在回调返回之后才会。
    tracedService.processResult();
  });
});
```

## 4. AsyncNarrativeContext

`AsyncNarrativeContext` 封装了 Node 的 `AsyncLocalStorage`,以提供按请求划分的追踪隔离:

```ts
import { AsyncNarrativeContext, NarrativeTraceConfig } from "@narrativetrace/core";

const config = new NarrativeTraceConfig();
const asyncContext = new AsyncNarrativeContext(config);

// 每次 run() 都会创建一个隔离的 SyncNarrativeContext
asyncContext.run(() => {
  // 这里的所有追踪调用都是隔离的
  tracedService.placeOrder("C1", "P1", 2);
  const tree = asyncContext.captureTrace(); // 只包含本次 run 的事件
});
```

### 工作原理

- `run(fn)` —— 在 `AsyncLocalStorage` 内部创建一个新的 `SyncNarrativeContext` 并执行 `fn`
- 所有 `enterMethod`/`exitMethodWithReturn`/`exitMethodWithException` 调用都委托给当前的 store
- `captureTrace()` 只返回当前 store 的追踪树
- 若在 `run()` 之外调用,则委托给一个默认上下文

### 并发请求隔离

```ts
// 请求 1 和请求 2 并发运行
asyncContext.run(() => {
  // 请求 1 的追踪是隔离的
  tracedService.handleOrder("order-1");
});

asyncContext.run(() => {
  // 请求 2 的追踪是隔离的
  tracedService.handleOrder("order-2");
});
```

## 5. 手动集成(SyncNarrativeContext)

无需中间件即可完全手动控制:

```ts
import { NarrativeTraceConfig, SyncNarrativeContext, renderIndentedText } from "@narrativetrace/core";
import { traceObject } from "@narrativetrace/proxy";

const config = new NarrativeTraceConfig();
const context = new SyncNarrativeContext(config);

// 追踪服务
const orderService = traceObject(new DefaultOrderService(/* deps */), context);

// 运行业务逻辑
orderService.placeOrder("C1", "P1", 2);

// 捕获并渲染
const tree = context.captureTrace();
console.log(renderIndentedText(tree));

// 为下一次操作重置
context.reset();
```

### ContextSnapshot(跨边界传播)

传播是双向的。快照会把追踪 id、发起调用的 span 以及请求元数据带 *进* 异步工作;而在那里被
追踪的工作也会 **传回来**:发起该快照的上下文会报告它——从调用被发布的那一刻起,而不是只在
作用域关闭之后。

```ts
const snapshot = context.snapshot();

// 在另一个上下文作用域中激活
const scope = snapshot.activate(otherContext);
try {
  tracedService.processOrder("order-1");
} finally {
  scope.close(); // 把工作交还给 `context`,然后结束这次活跃注册
}

// 或者使用便捷包装器
snapshot.wrapFn(otherContext, () => {
  tracedService.processOrder("order-1");
});

// 当你自己发布子调用时选择退出——ForkJoinGroup 和 FireAndForgetGroup 就是这样做的。
// 在每一跳都不注册、不交还任何内容。
const detached = snapshot.activateWithoutAdoption(otherContext);
```

位置由 **提交** 时刻决定:如果在发起调用仍处于打开状态时拍摄快照,那么这份工作会成为该调用
的子级;如果在调用已经返回之后拍摄,那么这份工作会成为同一追踪的下一个根节点。在已激活的快照
下打开的第一个 span 会被标记为 `concurrency.kind === "async"`。

接纳(adoption)是有上限的——每个上下文 10,000 个 span;一批会越过上限的接纳会被
**整批** 拒绝,而不是让父级被挡在外面、子级却孤零零地留下。这些拒绝会与捕获缓冲区自身的
丢弃一起计入 `context.traceLoss()`。

## 6. NestJS

`@narrativetrace/nestjs` 包提供了 `AutoProxyModule`,它会自动为每个 provider 加上代理,
使服务调用得以被捕获,而无需改动你的业务代码。它会运行一个按请求划分的上下文,并在完成时
触发一个携带已捕获追踪树的钩子。

```ts
import { AutoProxyModule, NoAutoProxy } from "@narrativetrace/nestjs";
import { Module } from "@nestjs/common";

@Module({
  imports: [
    AutoProxyModule.forRoot({
      serviceName: "orders-api",
      level: "detail",
      // 一条真实的管道(例如接入 pino/winston/otel)——没有它,追踪
      // 只会被捕获,而不会被导出。
      pipeline,
      // 需要保持不被追踪的 provider。
      exclude: [HealthController],
      // 每次请求结束后触发,携带已捕获的追踪树、HTTP 状态码和耗时。
      onRequestComplete: (ctx, { statusCode, durationMs, tree }) => {
        console.log(statusCode, durationMs, tree);
      },
    }),
  ],
  providers: [OrderService],
})
export class AppModule {}

// 让单个 provider 退出自动代理:
@NoAutoProxy()
export class LegacyService {}
```

### 工作原理

- `AutoProxyModule` 是一个全局模块:它把已注册的 provider 包装进 `traceObject()` 代理中,并为每个请求打开一个全新的上下文。
- 它导出了 `NarrativeStorage`,即按请求划分的上下文持有者——在需要直接访问当前上下文的地方注入它。
- `@NoAutoProxy()` 用于标记单个 provider,使其在自动代理阶段被跳过。
- 每次请求结束后,`onRequestComplete(ctx, { statusCode, durationMs, tree })` 会携带已捕获的 `tree` 触发,让你可以渲染、导出或转发这段叙述。一次被捕获的请求会产生一棵追踪树,涵盖处理该请求过程中发生的每一次被代理的服务调用。

## 7. React 与 React Router

`@narrativetrace/react` 包会根据你的方法名和参数名捕获组件与服务的追踪——组件中无需任何
日志样板代码。用 `NarrativeTraceProvider` 包裹组件树,用 `useTraced` 追踪一个服务,再用
`useTraceCapture` 取出已捕获的追踪树:

```tsx
import {
  NarrativeTraceProvider,
  useTraced,
  useTraceCapture,
} from "@narrativetrace/react";
import { CheckoutService } from "./checkout-service";

function Checkout() {
  const checkout = useTraced(() => new CheckoutService(), "CheckoutService");
  const { captureAndReset } = useTraceCapture();

  function onPlaceOrder() {
    checkout.placeOrder("C1", "P1", 2);
    const tree = captureAndReset();
    console.log(tree.roots);
  }

  return <button onClick={onPlaceOrder}>Place order</button>;
}

export function App() {
  return (
    <NarrativeTraceProvider level="detail">
      <Checkout />
    </NarrativeTraceProvider>
  );
}
```

`useNarrativeTrace()` 返回原始上下文,`useTracedFetch()` 返回一个会在发出请求上盖上
`traceparent` 戳记的 `fetch`。

### React Router 导航捕获

`@narrativetrace/react-router` 包会在每次导航时捕获一棵全新的追踪树,使每次路由切换都
产生一段自成一体的追踪。在你的路由器内部渲染一个调用 `useNavigationCapture` 的组件——每当
路径名发生变化,它就会捕获累积的追踪、把它交给你的回调,并重置上下文:

```tsx
import { NarrativeTraceProvider } from "@narrativetrace/react";
import { useNavigationCapture } from "@narrativetrace/react-router";
import type { TraceTree } from "@narrativetrace/core";
import { BrowserRouter } from "react-router-dom";

function NavigationTracer() {
  useNavigationCapture((tree: TraceTree) => {
    console.log("captured on navigation", tree.roots);
  });
  return null;
}

export function App() {
  return (
    <BrowserRouter>
      <NarrativeTraceProvider>
        <NavigationTracer />
        {/* 路由 */}
      </NarrativeTraceProvider>
    </BrowserRouter>
  );
}
```

回调是可选的——省略它就只会在每次导航时重置追踪。`useNavigationCapture` 必须同时在
`NarrativeTraceProvider` 和 React Router 上下文中使用。

## 8. OpenTelemetry

`@narrativetrace/opentelemetry` 包把方法调用叙述映射为 OTel span,因此现有的
Jaeger/Tempo/Datadog 视图无需手工埋点 span 即可正常呈现。`createOtelEventConsumer` 是
实时桥接器——它会随方法执行开始/结束 span,并把子 span 嵌套在其父级之下。将它接入一条
管道:

```ts
import { AsyncNarrativeContext, DualPathPipeline, NarrativeTraceConfig } from "@narrativetrace/core-node";
import { createOtelEventConsumer } from "@narrativetrace/opentelemetry";
import { trace } from "@opentelemetry/api";

const tracer = trace.getTracer("orders");
const consumer = createOtelEventConsumer({ tracer, maxActiveSpans: 1024 });

const pipeline = new DualPathPipeline(consumer, null);
const context = new AsyncNarrativeContext(new NarrativeTraceConfig("detail"), pipeline);
```

对于事后导出,`TraceSpanExporter` 可以一次性把已捕获的 `TraceNode` 树转换为嵌套的 span:

```ts
import { TraceSpanExporter } from "@narrativetrace/opentelemetry";

new TraceSpanExporter(tracer).export(roots);
```

### 属性词汇表

每个 span 都会被盖上 `nt.trace_id` 以及其他 `nt.*` schema 属性(追踪身份、深度、并发性、
级别),再加上为方法参数准备的、带类型的 `narrative.param.<name>` 值。这些 span 属性映射
函数——`setSpanAttributes`、`setNtSchemaAttributes`、`setOutcomeAttributes`、
`buildEventAttributes` 等等——都已导出,便于构建自定义导出器。

## 9. Winston 与 Pino

`@narrativetrace/winston` 和 `@narrativetrace/pino` 包会把方法调用事件以结构化的、
逐事件一行的形式(进入时为 `→ Class.method`,退出时为 `← returned: …` / `!! Error`)
流式写入你的日志器,携带 `code.*`、`trace_id`、`service.*`、`nt.depth` 以及带类型的参数。

### Winston

```ts
import { AsyncNarrativeContext, DualPathPipeline, NarrativeTraceConfig } from "@narrativetrace/core-node";
import { createWinstonEventConsumer } from "@narrativetrace/winston";
import winston from "winston";

const logger = winston.createLogger({ format: winston.format.json() });

// 进入/返回默认级别为 `debug`,异常默认为 `warn`——可按事件类型逐一覆盖。
const consumer = createWinstonEventConsumer(logger, {
  levels: { enter: "info", return: "info", exception: "error" },
});

const pipeline = new DualPathPipeline(consumer, null);
const context = new AsyncNarrativeContext(new NarrativeTraceConfig("detail"), pipeline);
```

要把当前活跃的追踪身份盖印到你 *自己* 的 `logger.*` 调用上,请把 `createWinstonFormat()`
加入日志器的格式链——它会把当前的 `LogContext`(`trace_id`、`service.*`、`nt.depth`)
合并进每一行日志。

### Pino

```ts
import { AsyncNarrativeContext, DualPathPipeline, NarrativeTraceConfig } from "@narrativetrace/core-node";
import { createPinoEventConsumer } from "@narrativetrace/pino";
import pino from "pino";

const logger = pino();

// 进入/返回默认级别为 `trace`(pino 有真正的 TRACE 级别),异常默认为 `warn`。
const consumer = createPinoEventConsumer(logger, {
  levels: { enter: "info", return: "info", exception: "error" },
});

const pipeline = new DualPathPipeline(consumer, null);
const context = new AsyncNarrativeContext(new NarrativeTraceConfig("detail"), pipeline);
```

要把当前活跃的追踪身份盖印到你 *自己* 的 `logger.*` 调用上,请把 `createPinoMixin()`
作为日志器的 `mixin` 传入——它会把当前的 `LogContext`(`trace_id`、`service.*`、
`nt.depth`)合并进每一行日志。

### 按事件划分的级别

两个 consumer 都接受一个以事件类型(`enter`、`return`、`exception`)为键的 `levels`
映射,因此你可以把进入/返回的噪音级别提升到 `info`,或者把异常单独推到 `error`。Winston
的默认值为 `debug`/`debug`/`warn`;Pino 的默认值为 `trace`/`trace`/`warn`。
