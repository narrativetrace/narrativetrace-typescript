# NarrativeTrace TypeScript — 功能指南

[English](../feature-guide.md) | [Español](../es/guia-de-funcionalidades.md) | [Português](../pt-BR/guia-de-funcionalidades.md) | **简体中文**

从用户视角看,**本移植版**提供了什么。涵盖所有平台的规范功能目录——每一项
NarrativeTrace 功能在每个平台上的权威状态用语——位于
[Java 旗舰版的功能指南](https://github.com/narrativetrace/narrativetrace-java/blob/main/documentation/feature-guide.md)。
本文件刻意保持精简:它只记录 TypeScript 包交付了什么、与规范目录的差异之处,
以及这个平台接下来会有什么——机制层面的*原因*(装饰器 + ES Proxy 相对于
loader-hook 插桩、平台包的拆分、有界缓冲管道)属于内部工程记录,不在此重复。

**状态标签**(与规范指南使用相同的用语):

- **免费** —— 已在本仓库中发布,源码可得,基于 [BSL 1.1](../../LICENSE)
  (SPDX `BUSL-1.1`),每次发布四年后转为 Apache 2.0。注解/装饰器 API、
  输出格式规范与清晰度评分标准均为 Apache 2.0 开放标准。
- **Pro** —— 已在商业层级中发布。
- **开发中** —— 正在积极构建;设计已定。
- **已规划** —— 已有规格说明,尚未开始;可能变更。

## 捕获你代码的故事(核心追踪)

| Feature | Status | Notes |
|---|---|---|
| 通过 ES `Proxy` 实现自动叙事捕获——类、方法、参数、返回值、耗时、错误;零日志语句 | 免费 | 来自 `@narrativetrace/proxy` 的 `traceObject(service, context)` |
| 装饰器——`@traced`(参数名称)、`@narrated`(带 `{param}` 模板的叙述)、`@onError`(错误上下文模板)、`@notTraced`(脱敏) | 免费 | TC39 stage-3 装饰器,TS 5.0+;[decorators-guide.md](装饰器指南.md) |
| 面向纯 JS 的编程式 API——`traceObject(service, context, { method: ["paramA", …] })` 名称映射,以及底层 `NarrativeContext` 的 enter/exit API | 免费 | 不支持装饰器时的完整功能集 |
| 敏感数据脱敏——`@notTraced` 索引、`static notTraced` 字段列表、基于名称模式的 `RedactionPolicy` 拒绝列表(`password`、`token` 等);被脱敏的值不会通过叙述/错误模板泄漏 | 免费 | |
| 五个捕获级别(`off` → `errors` → `summary` → `narrative` → `detail`),可通过 `config.level` 在运行时切换;Node 上可用 `NARRATIVETRACE_LEVEL` 环境变量 | 免费 | 级别名称与 Java 略有不同(`summary` 对应 `FLOW`);`off` 会在任何捕获工作开始前短路 |
| 双闸门级别——捕获级别与日志器级别(winston/pino 配置)相互独立 | 免费 | 产品 ADR-008 |
| 即时值序列化——值在调用时即渲染为字符串;不保留对象引用,循环引用安全,有截断限制 | 免费 | 参见 README 的 FAQ 以及装饰器指南中的纯净性契约 |
| 追踪身份——traceId、人类可读的追踪名称、storyId/chapterId、跨服务的 W3C `traceparent` 继承 | 免费 | 与规范 schema 对齐;`examples/` 中有分布式演示 |

**平台限制(先说清楚)。** JavaScript 在运行时不保留参数名称——如果没有
额外帮助,参数会渲染为 `arg0`、`arg1`、……。因此二级(Tier-2)注解在这里
比在 JVM 上分量更重:`@traced("customerId", …)` 或 `paramNames` 映射才是
追踪获得真实名称的方式,而压缩工具(minifier)会让这在生产构建中成为
必需。参见平台 ADL 中的 TS-004。

## 让本指南保持诚实

改编自规范指南对精简版平台指南所定的规则:

1. **本移植版**每个用户可见的功能都在此出现,且恰好出现一次,并标注状态。
   跨平台的功能定义与完整目录只存在于规范指南中——本文件绝不重复陈述
   本移植版未交付或未规划的功能。
2. 功能只有在相关 TS 仓库中完成合并、测试并写好文档之后,才能进入
   **免费**/**Pro**。“开发中”表示设计已定且工作已排期;“已规划”表示
   仅有规格说明。
3. 在本仓库中新增或提升某项功能状态的变更,必须在同一个 commit 中更新
   本文件——如果该功能对整个产品而言是全新的(不只是对本移植版而言),
   还必须同时更新规范指南。
4. 当 TS 的行为与规范描述不同时(级别名称、运行时参数名称、没有 agent
   式插桩),差异会在此明确说明,而不是被悄悄抹平。
