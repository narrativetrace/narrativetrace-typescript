# NarrativeTrace TypeScript 安装指南

[English](../installation-guide.md) | [Español](../es/guia-de-instalacion.md) | [Português](../pt-BR/guia-de-instalacao.md) | **简体中文**

本指南介绍如何在 Node.js 或浏览器项目中安装并接入 NarrativeTrace TypeScript。

## 前提条件

- Node.js 20+
- pnpm（或 npm/yarn）

## 快速开始

```bash
pnpm add @narrativetrace/core-node @narrativetrace/proxy   # Node(浏览器中请使用 @narrativetrace/core-web)
```

```ts
import { NarrativeTraceConfig, SyncNarrativeContext, renderIndentedText } from "@narrativetrace/core-node";
import { traceObject } from "@narrativetrace/proxy";

const context = new SyncNarrativeContext(new NarrativeTraceConfig());
const traced = traceObject(orderService, context);

traced.placeOrder("C1", "P1", 2);
console.log(renderIndentedText(context.captureTrace()));
```

## 1. 添加依赖

先从最小依赖组合开始，再按需添加你需要的集成。

```bash
# 最小依赖 —— 根据你的运行时选择平台入口
pnpm add @narrativetrace/core-node @narrativetrace/proxy   # Node
pnpm add @narrativetrace/core-web @narrativetrace/proxy    # 浏览器 / Web Worker

# `core-node` 和 `core-web` 会重新导出 `@narrativetrace/core` 中的所有内容，并注册
# 平台优化过的 id 生成器(node:crypto 与 Web Crypto 二选一)。仅使用 `@narrativetrace/core`
# 依然可以正常工作——它会在 Web Crypto 可用时(本库支持的每种运行时都可用)直接回退到它——
# 但平台包仍然是应当安装的那个:它是经过测试、有文档记录的路径,也是唯一保证在完全没有
# Web Crypto 的运行时上不会抛出异常的路径。

# 可选集成
pnpm add -D @narrativetrace/vitest           # Vitest 插件
pnpm add @narrativetrace/diagrams            # Mermaid + PlantUML
pnpm add @narrativetrace/clarity             # 命名清晰度分析
pnpm add @narrativetrace/browser             # 浏览器控制台 + 网络导出
pnpm add @narrativetrace/standalone          # 面向纯 <script> 页面的单文件打包产物(无需打包工具)
```

## 2. 选择集成路径

### 选项 A：ES Proxy（适用于任何 TypeScript/JavaScript 应用）

```ts
// Node: "@narrativetrace/core-node" —— 浏览器: "@narrativetrace/core-web"
import { NarrativeTraceConfig, SyncNarrativeContext, renderIndentedText } from "@narrativetrace/core-node";
import { traceObject } from "@narrativetrace/proxy";

const config = new NarrativeTraceConfig();
const context = new SyncNarrativeContext(config);

const tracedOrderService = traceObject(orderService, context, {
  placeOrder: ["customerId", "productId", "quantity"],
});

tracedOrderService.placeOrder("C1", "P1", 2);
console.log(renderIndentedText(context.captureTrace()));
context.reset();
```

当你希望对追踪拥有显式控制权时，使用这种方式。适用于 Node、Deno、Bun 和浏览器。

### 选项 B：Vitest 插件（自动上下文 + 追踪输出）

```bash
pnpm add -D @narrativetrace/vitest @narrativetrace/proxy vitest
```

`vitest` 是 `@narrativetrace/vitest` 唯一的 peerDependency(对等依赖）；它的另外四个 NarrativeTrace 依赖包(core-node、clarity、diagrams、glossary)会随它一起自动安装——它们与它同步发布，从不单独设定版本号。之所以显式写出 `@narrativetrace/proxy`，是因为下面的示例直接从它导入 `traceObject`:pnpm 只会暴露一个包自身的依赖，不会暴露依赖的依赖,所以任何你自己 `import` 的东西都必须是你自己项目的直接依赖(npm 更扁平的 `node_modules` 不区分这一点,但这里演示的 pnpm 会区分)。*(since 0.1.3, unreleased)*

#### 基础夹具（无文件输出）

```ts
import { narrativeTest } from "@narrativetrace/vitest";
import { traceObject } from "@narrativetrace/proxy";

narrativeTest("customer places order", ({ narrativeContext }) => {
  const traced = traceObject(orderService, narrativeContext);
  traced.placeOrder("C1", "P1", 2);
  // narrativeContext 可用于断言
});
```

#### 带文件输出

```ts
import { createNarrativeTest } from "@narrativetrace/vitest";
import { traceObject } from "@narrativetrace/proxy";

const test = createNarrativeTest({
  outputDir: "narrativetrace-output",
  formats: ["md", "json", "mmd", "puml", "clarity-json"],
});

test("customer places order", ({ narrativeContext }) => {
  const traced = traceObject(orderService, narrativeContext);
  traced.placeOrder("C1", "P1", 2);
});
```

特性：
- 通过 Vitest 夹具为每个测试提供 `NarrativeContext`
- 每次测试后自动生成追踪文件
- 场景名称派生自测试名称
- 多种输出格式：Markdown、JSON、Mermaid、PlantUML、清晰度 JSON

### 选项 C：Express/Hono 中间件

在 Web 应用中使用 `AsyncNarrativeContext` 实现按请求追踪：

```ts
import { AsyncNarrativeContext, NarrativeTraceConfig, renderIndentedText } from "@narrativetrace/core";
import { traceObject } from "@narrativetrace/proxy";
import express from "express";

const config = new NarrativeTraceConfig();
const asyncContext = new AsyncNarrativeContext(config);

const app = express();

app.use((req, res, next) => {
  asyncContext.run(() => {
    // 该请求内所有被追踪的调用都共享同一个上下文
    next();
  });
});

app.get("/orders", (req, res) => {
  const traced = traceObject(orderService, asyncContext);
  const result = traced.placeOrder("C1", "P1", 2);
  console.log(renderIndentedText(asyncContext.captureTrace()));
  res.json(result);
});
```

### 选项 D：浏览器（控制台渲染 + 网络导出）

```bash
pnpm add @narrativetrace/core-web @narrativetrace/proxy @narrativetrace/browser
```

```ts
// core-web 会注册 Web Crypto id 生成器 —— 请导入它，而不是 @narrativetrace/core
import { NarrativeTraceConfig, SyncNarrativeContext, renderIndentedText } from "@narrativetrace/core-web";
import { traceObject } from "@narrativetrace/proxy";
import { renderToConsole, postToCollector } from "@narrativetrace/browser";

const context = new SyncNarrativeContext(new NarrativeTraceConfig());
const traced = traceObject(orderService, context);

traced.placeOrder("C1", "P1", 2);
const tree = context.captureTrace();

// 在页面中显示它
document.querySelector("pre#trace").textContent = renderIndentedText(tree);

// 同步镜像到 DevTools 控制台
renderToConsole(tree);

// 以 JSON 形式 POST 到采集端点(无论 HTTP 状态码为何都会 resolve —— 请检查 response.ok)
const response = await postToCollector(tree, { scenario: "place order" }, "https://your-collector.example.com/traces");
```

核心上下文、ES Proxy 与值渲染都是纯 JavaScript 实现，零 Node 依赖。`AsyncLocalStorage` 仅限 Node 使用；在浏览器中，需要通过 `snapshot()` 手动传播上下文。
可运行版本：`pnpm run example:browser`（参见 [示例指南](示例指南.md#浏览器)）。

### 选项 E：纯 JavaScript 页面，无需打包工具（script 标签）

```bash
pnpm add @narrativetrace/standalone
```

`@narrativetrace/standalone` 提供一个包含 `core-web` + `proxy` + `browser` 的单文件，有两种形式：`dist/narrativetrace.global.js`（经典 script → `window.NarrativeTrace`）和 `dist/narrativetrace.js`（ES 模块）。把你需要的那个文件复制到页面旁边；加载它就会注册浏览器 id 生成器，因此不需要再导入其他任何东西。

```html
<script src="narrativetrace.global.js"></script>
<script>
  var NT = window.NarrativeTrace;
  var context = new NT.SyncNarrativeContext(new NT.NarrativeTraceConfig());
  var traced = NT.traceObject(orderService, context, { placeOrder: ["customerId", "productId", "quantity"] });

  traced.placeOrder("C1", "P1", 2);

  var tree = context.captureTrace();
  document.getElementById("trace").textContent = NT.renderIndentedText(tree);
  NT.renderToConsole(tree);
</script>
```

可运行版本：`pnpm run example:script-tag`（参见 [示例指南](示例指南.md#script-标签)）。如果你已经有可用的打包工具，请优先选择选项 A/D —— 依赖图更小，并支持 tree-shaking。

## 3. 配置追踪输出

### Vitest（推荐）

使用带选项的 `createNarrativeTest`：

```ts
const test = createNarrativeTest({
  outputDir: "narrativetrace-output",   // 默认值："narrativetrace-output"
  formats: ["md", "json"],              // 默认值：["md", "json", "mmd"]
  bufferCapacity: 8192,                 // 默认值：8192 个事件(约 4,000 次被追踪的调用)
});
```

如果一个测试追踪的事件数超过 `bufferCapacity` 所能容纳的上限，就会丢失最早的事件。这不会悄无声息地发生：运行时会打印一行，注明事件数量以及应调高到的数值，Markdown 与图表产物也会带有相同的页脚说明。

可用格式：

| 格式 | 扩展名 | 内容 |
|--------|-----------|---------|
| `md` | `.md` | 带 YAML frontmatter 的 Markdown |
| `json` | `.json` | 带 enter/exit 事件的 JSON |
| `mmd` | `.mmd` | Mermaid 时序图 |
| `puml` | `.puml` | PlantUML 时序图 |
| `clarity-json` | `.clarity-json` | 清晰度分析 JSON |

### 手动输出

对于非 Vitest 场景，直接使用渲染器：

```ts
import { renderMarkdown, renderIndentedText, renderProse, exportJson } from "@narrativetrace/core";
import { renderMermaidSequence, renderPlantUmlSequence } from "@narrativetrace/diagrams";

const tree = context.captureTrace();

// 选择你需要的格式
console.log(renderIndentedText(tree));
console.log(renderMarkdown(tree, { scenarioName: "Order placement" }));
console.log(renderProse(tree));
console.log(exportJson(tree, { scenario: "Order placement" }));
console.log(renderMermaidSequence(tree));
console.log(renderPlantUmlSequence(tree));
```

## 4. 验证安装

运行测试：

```bash
pnpm test
```

如果使用了 `createNarrativeTest`，追踪文件会出现在配置的输出目录中：

```
narrativetrace-output/
├── customer_places_order.md
├── customer_places_order.json
├── customer_places_order.mmd
├── customer_places_order.puml
└── customer_places_order.clarity-json
```
