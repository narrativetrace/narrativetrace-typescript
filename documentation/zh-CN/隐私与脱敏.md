# 隐私与脱敏

[English](../privacy-and-redaction.md) | [Español](../es/privacidad-y-ocultacion.md) | [Português](../pt-BR/privacidade-e-ocultacao.md) | **简体中文**

这个库运行在你的进程内部,写出的文件会被你的团队共享——测试产物、CI 输出、生产日志行。这一页是这份契约逐行展开的版本:哪些内容会被脱敏、脱敏能覆盖到哪里、覆盖不到哪里,以及 NarrativeTrace 保证什么、又完全不对什么做出承诺。已于 2026-09-02 逐行对照代码验证过,不是从文档里推断出来的。

## 脱敏,逐个界面来看

| 界面 | 能否关闭内置脱敏? |
|---|---|
| `traceObject()`(proxy)——下面每一种集成都构建在其上的唯一捕获路径 | 不能 |
| Vitest 夹具(`createNarrativeTest`/`narrativeTest`) | 不能 |
| Express / Hono / NestJS 中间件 | 不能 |
| Angular / React 集成 | 不能 |
| 你自己的代码直接调用 `renderValue()`/`renderStructured()` | 能——但只有显式传入 `{ redactionPolicy: RedactionPolicy.DISABLED }` 才行,而且即便如此,`@notTraced`/`static notTraced` 依然会脱敏(见下文) |
| `@notTraced` / `static notTraced` | 不适用——它本身就是执行脱敏的那一方,并且在每一个界面上都永远优先,包括一个 `RedactionPolicy.DISABLED` 的渲染器 |

以下结论对照代码验证过,不是推断出来的:`traceObject()`——每一个随包发布的集成(`express`、`hono`、`nestjs`、`angular`、`react`、`vitest`……)都构建在其上的唯一捕获路径——从不会把调用方传入的 `redactionPolicy` 选项一路透传下去。`redactionPolicy` 选项只存在于底层的渲染函数上(`@narrativetrace/core` 里的 `renderValue`/`renderStructured`),而没有任何一个随包发布的集成暴露过覆盖它的办法。到达 `RedactionPolicy.DISABLED` 的唯一办法,是应用代码直接调用这些函数——这是你自己源码里一个刻意的、可审查的行为,而不是部署时可能被翻转的配置开关或环境变量。

## 什么会脱敏,以及谁压过谁

每一个被捕获/渲染的值,都会受到三种彼此独立的机制作用:

1. **方法参数上的 `@notTraced(i)`**——*调用方*(`traceObject` 的值映射构建器)会在任何叙述/错误模板被解析之前,就把值替换成 `[REDACTED]` 标记,所以模板解析器在这一环节上从未真正持有过这个秘密值。
2. **类上的 `static notTraced = [...]`**——针对对象内省和 `{param.property}` 模板路径的字段名脱敏。这项检查与当前生效的是哪个 `RedactionPolicy` 无关:「这个成员是否被显式标注过」这个答案是直接从类本身算出来的,然后按 `annotated || nameMatchesDenyList` 的方式组合,所以即便是在一个把所有名称模式和值形状检查都关掉的策略下,显式标注依然会脱敏。
3. **基于名称的拒绝列表**(`RedactionPolicy.DEFAULT`)——把字段名与一份不区分大小写的子串集合(`password`、`secret`、`token`、`apikey`、`cvv`、`ssn`、`authorization`、`credential`、`cardnumber`、`jwt`、`cookie`、`sessionid`、`accountnumber`、`routingnumber`、`pan`、`iban`,以及它们对应的 `snake_case` 写法)进行匹配,再加上对值本身*形状*的第二重独立检查——是不是 JWT(`eyJ…`)、是不是符合 Luhn 校验的卡号、是不是一个 `Set-Cookie` 形状的字符串——这样一来,一个没有名字的值(列表里的一项、map 里的一个值),或者一个挂在未识别名称下的持有者令牌,依然会被捕获。`"companyName"`/`"panelId"` 不会匹配 `pan`——最容易产生误报的这两个模式(`pan`、`iban`)只在标识符词边界上匹配,而不是裸子串匹配。

**精心编写的 `toString()`** 通常会被按原样信任——但一个声明了任意 `static notTraced` 字段的类,会被改为逐字段内省,所以这时候遵从的是这个注解,而不是那个 `toString()` 原本会打印出来的内容。模板解析同样没有绕开这一点的捷径:已经审计过,确保它不会在安全渲染因为无关原因(字段/深度上限触发的截断)而恰好省略了标记时,退回去使用值的原始 `toString()`——每一个非标量的占位符值,都无条件地经过与追踪其余部分相同的、执行字段级脱敏的渲染器。

脱敏还**能在嵌套结构中存活**——一个被脱敏的成员,不管是在数组、`Set`、`Map`、普通对象里,还是这些结构层层叠加,乃至一个自引用的循环里,都由测试固定住了这一行为(`redacted-value-containment.test.ts`)。它还**会压过点名它的叙述模板**:`@narrated`/`@onError` 里的 `{param.property}` 在解析到一个指向被脱敏成员的路径时,结果始终是 `[REDACTED]`,绝不是字面值——这一点通过真实的捕获路径端到端地固定住了,特别包括「整对象占位符、默认字段转储」这种情形(对象本身完全没有自定义的 `toString()`)。

完整细节与实例见[装饰器指南 § `@notTraced`](装饰器指南.md#nottraced)。

## 保证

- **追踪失败与宿主执行是隔离的。** 捕获在设计上就是尽力而为的:解析名称、渲染参数或进入一个 span 时发生的任何失败,都会降级为一次未被追踪的调用,而绝不会阻塞或让业务方法失败(这是 `trace-object.ts` 自己的「不投毒契约」)。一个会抛异常的自定义 `toString()`、一个在模板里被点名的抛异常 getter,或者一个已满的缓冲区,都不会改变你的方法返回什么或抛出什么。
- **每一个随包发布的集成都遵守脱敏规则。** 见上面的表格——没有任何一个集成暴露过绕开它的办法。
- **带缓冲的分析路径可能会丢弃事件,但它总会报告丢失。** 它绝不会阻塞调用方,也绝不会超出自己的容量上限(一个固定大小的环形缓冲区,在 Vitest 夹具里默认是 `8,192` 个事件,在长期运行的进程里更高——见[配置指南 § 8](配置指南.md#8-事件管道缓冲bufferedeventconsumer))。一次丢过事件的捕获,会在自己的 footer 里打印丢失的数量,以及应该把容量提高到多少。

## 不做的承诺

- **没有「零开销」这种说法。** 追踪确实做了工作,而工作是有代价的——见 [README 的性能小节](../../自述文件.md#性能)。
- **不追踪私有字段,但也没有接口要求。** `#private` 类字段完全无法被 `Proxy` 拦截——这是 JavaScript 语言本身的限制。与 JVM 的动态代理不同,这里不需要先实现某个接口;任何能通过属性查找到达的方法——不管是声明在对象本身上,还是从其原型链继承来的——对 `traceObject()` 来说都是可见的。
- **目前还没有不携带值的结构化产物。** 其他一些 NarrativeTrace 移植版本也提供一种 `.nt` 风格的产物,完全不含运行时的值,可以交给 AI 工具使用,在结构上就不存在提示注入面。这个移植版本还没有构建出这个东西——见[应提交的内容](应提交的内容.md#为什么这里还没有-approvednt-这一行)。在它出现之前,这个移植版本生成的每一份产物都携带真实的捕获值,应当按此对待。
- **没有零代码、「包装一个你没写过的应用」这条路。** 这个平台上没有 Java agent 那样的等价物,所以范围划定始终要靠显式的调用点或类注解——见[选择集成方式 § 平台上限](选择集成方式.md#平台上限)。

## 这一页没有涵盖的内容

当 NarrativeTrace 与另一个同样包装了相同对象的库——一个 DI 容器、另一个 `Proxy`、一个契约库——叠加使用时会发生什么。简单来说:NarrativeTrace 只叙述业务边界的跨越,而哪一层包装器处在「更外层」,永远不会改变被脱敏的值、业务结果,或是最终进入叙述的异常——完整的共存契约见 [README 的 FAQ](../../自述文件.md#narrativetrace-如何与其他包装方法的库aop代理契约库交互)。
