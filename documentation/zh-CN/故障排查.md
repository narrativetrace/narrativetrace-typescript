# 故障排查

[English](../troubleshooting.md) | [Español](../es/solucion-de-problemas.md) | [Português](../pt-BR/solucao-de-problemas.md) | **简体中文**

症状 → 原因 → 解决办法,针对大家实际会遇到的失败模式。有些条目是完整的
解释;有些则指向已经更详细地讲过这件事的指南,而不是在这里重复一
遍——一个事实只有一个家。

## 参数显示为 `arg0`、`arg1`

**原因:** JavaScript 在运行时不会保留参数名——不像 JVM 有 `-parameters`
编译器参数可以恢复它们,这里没有任何编译器参数能做到这一点。没有额外
帮助时,`traceObject()` 会退回使用按位置命名的参数名。

**解决办法:** 两种方式都可以提供参数名——

```ts
class OrderService {
  @traced("customerId", "productId", "quantity")
  placeOrder(customerId: string, productId: string, quantity: number) { /* ... */ }
}
```

或者,不使用装饰器:

```ts
traceObject(orderService, context, { placeOrder: ["customerId", "productId", "quantity"] });
```

压缩后的生产环境打包产物同样会去掉参数名,所以这不只是开发环境才会遇
到的问题——参见[装饰器指南 § `@traced`](装饰器指南.md#traced)。

## 没有写出追踪文件

**原因:** 几乎总是因为测试用的是不写文件的夹具(`narrativeTest`),而
不是会写文件的那个(`createNarrativeTest`)——这个实现刻意提供了
两个 Vitest 夹具,一个只用于断言,一个用于生成产物。较少见的情况是:
追踪树的根节点数为零(没有任何调用经过被追踪的对象),而
`writeTraceOutput` 在设计上对空追踪什么都不写,所以一个没有捕获到任何
span 的测试套件不会留下任何目录。

**解决办法:** 使用 `createNarrativeTest`(参见
[前 10 分钟](前10分钟.md#3-添加一个-vitest-测试)),并检查被测调用是
否确实经过了被追踪的包装对象——如果调用的是未包装的实例,而不是
`traceObject()` 返回的对象,就不会记录任何东西。

## 某个 getter 或字段始终不出现在追踪里

**原因:** `traceObject()` 包装的是方法,而不是任意属性。Getter 和非函
数属性会未经包装直接穿过 `Proxy`——读取 `traced.total` 会直接调用真正
的 getter,不会捕获任何东西。这是刻意为之:NarrativeTrace 叙述的是*调
用*,而从调用方的角度看,读取一个 getter 和读取一个普通属性没有区别。

**解决办法:** 如果这个值对追踪很重要,要么从一个被追踪的方法里把它返
回出来,要么在 `@narrated`/`@onError` 模板中按名称引用这个属性
(`{order.total}`)——属性路径解析*确实*会在渲染时调用一次 getter。参
见[装饰器指南](装饰器指南.md#纯净性契约--追踪期间的副作用)中的纯净性
契约。

## `@traced`/`@notTraced` 装饰器无法应用或无法编译

**原因:** 这两个是 TC39 stage-3 方法装饰器,需要 TypeScript 5.0 及以
上版本。`tsconfig.json` 中旧式的 `experimentalDecorators: true` 使用
的是另一种更旧的装饰器形态,不接受这个实现所生成的 stage-3 语法。

**解决办法:** 升级到 TypeScript 5.0 及以上版本,并从 `tsconfig.json`
中移除 `experimentalDecorators`(以及 `emitDecoratorMetadata`,如果有
的话)。不需要任何其他编译器参数——stage-3 装饰器是 TypeScript 5 的默
认行为。

## 清晰度评分看起来不对

**原因:** 通常是 NLP 分析标记出的一个泛化命名——`get`、`set`、
`process`、`handle`、`data`、`info`、`temp` 以及类似的词,无论上下文
如何,评分都会偏低。

**解决办法:** 查看该场景 `.clarity-json` 中的 `issues` 数组(或者在接
入 `ClaritySuiteReporter` 之后查看测试套件的 `clarity-report.md`),把
被标记的名字换成一个领域专属的名字(`getData()` →
`fetchOrderHistory()`)。完整的评分模型参见
[清晰度指南](清晰度指南.md)——在
[前 10 分钟 § 6](前10分钟.md#6-把-placeorder-改名为-process看清晰度下降)
中把 `placeOrder` 改名为 `process`,重现的正是这次评分下降。

## 异步追踪缺失,或者后台任务始终不出现

**原因:** `AsyncNarrativeContext` 会跟随活动的 span 跨越 `await`,但
一个被启动后从未被 `await` 的任务(`setTimeout`、一个脱离的
promise、一个排队的任务)不会继承它——没有什么可以跟随,因为发起调用
早已返回。

**解决办法:** 用 `ForkJoinGroup`/`FireAndForgetGroup` 包装脱离的工
作,或者用 `context.snapshot()` + `snapshot.wrap(fn)` 手动嫁接。参见
[选择集成方式 § 各路径的注意事项](选择集成方式.md#各路径的注意事项)。

## `captureTrace()` 在另一个异步任务中返回空的或不完整的树

**原因:** 捕获是以上下文实例为作用域的,不像 JVM 实现那样以线程为
作用域——但 `SyncNarrativeContext`(浏览器环境)完全没有隐式传播,所
以在同一个上下文上两个未被 `await` 的重叠调用会互相破坏对方的
span,而不仅仅是丢失其中一个。

**解决办法:** 在 Node 上,使用 `AsyncNarrativeContext`。在浏览器环境
中,或者任何存在重叠工作的场景下,为每个并发任务使用显式的
fork/fire-and-forget 组,而不是在多个未被 `await` 的调用之间共享同一
个上下文。

## 捕获打印了 "NarrativeTrace dropped N events"

**原因:** 这不是一次失败——事件环形缓冲区(`BufferedEventConsumer`)
是一个固定大小的缓冲区,在 `createNarrativeTest` 中默认是 `8,192` 个
事件,如果测试追踪的调用数超过这个容量,就会丢弃最旧的事件,而不是无
限增长或阻塞调用方。确切的消息是:

```text
⚠️ NarrativeTrace dropped 16 events: the capture buffer (4) overflowed, so this narrative is incomplete. Raise it with createNarrativeTest({ bufferCapacity: 32 }).
```

**解决办法:** 把 `bufferCapacity` 提高到消息中给出的数值,或者缩小测
试所追踪的范围。容量与延迟的对照表,以及如何为生命周期更长的上下文确
定合适的大小,参见
[配置指南 § 8](配置指南.md#8-事件管道缓冲bufferedeventconsumer)。

## `@notTraced` 遮蔽了参数,但嵌套字段仍然显示

**原因:** 按参数索引脱敏(`@notTraced(i)`)和按字段级别脱敏
(`static notTraced = [...]`)是两种不同的声明。索引脱敏会把整个参数
清空;而在一个*未被脱敏*的参数内部,某个字段会被逐字段渲染出来,除非
这个字段本身按名称被加入了拒绝列表或被单独声明。

**解决办法:** 把这个字段加到该类自己的 `static notTraced` 列表里:

```ts
class Card {
  static readonly notTraced = ["cvv"];
  constructor(readonly last4: string, readonly cvv: string) {}
}
```

完整的约定,包括叙述模板如何处理一个被脱敏的路径,参见
[隐私与脱敏](隐私与脱敏.md)。

## NarrativeTrace 与其他代理或拦截器共存时的行为

这不是一份缺陷报告——而是一个每当某个服务已经被别的东西包装过(DI 容
器、另一个 `Proxy`、契约库)时就会出现的设计问题。NarrativeTrace 只叙
述业务边界的跨越,哪个包装器处于"外层"从来不会改变到达叙述的业务结果
或异常——完整的共存约定参见
[README 常见问题](../../自述文件.md#narrativetrace-如何与其他包装方法的库aop代理契约库交互)。
